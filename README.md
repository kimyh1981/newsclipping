# 뉴스클리핑

매일 아침 주요 신문(연합·조선·중앙·동아·한겨레·경향), 농업 신문(농민신문·한국농어민신문·농수축산신문·농축유통신문), 비료 관련 뉴스, 국제 정세·경제, 베트남 농업·비료 뉴스(단찌 등, 우리말 번역) 헤드라인을 모아,
**평일 아침 6~8시 차 블루투스가 연결되면 자동으로 읽어 주는** 앱입니다.
한국·베트남·영문 국제·중국·일본 언론 75곳 가운데 들을 언론사를 앱과 웹에서 각자 체크해 고릅니다 (외국 언론은 제목을 우리말로 번역).
원고는 아나운서처럼 요일에 맞춘 인사와 섹션 연결 말로 읽고, 안드로이드 앱에서는 폰에 든 한국어 음성 중 가장 자연스러운 음성을 골라 씁니다 (앱의 '듣기' 묶음에서 목소리와 말 빠르기를 들어 보고 바꿀 수 있습니다).
갤럭시 앱은 읽는 중에 **이전 · 전체 듣기 · 다음**으로 기사를 오가고, 전체 듣기는 듣던 기사의 본문 앞부분(약 1,200자)을 읽습니다. 차 핸들 버튼은 다음·이전 = 다음·이전 기사, 재생·일시정지 = 이어 듣기·멈춤입니다.
통화나 내비 안내가 끼어들면 멈췄다가 끝나면 멈춘 기사부터 이어 읽고, 다른 앱이 소리를 가져가면 멈춘 채 '이어 듣기'(앱 ▶, 알림, 핸들 재생)를 기다립니다(30분 지나면 끝).
서버 녹음은 차 스피커에서 'ㅅ' 소리가 날카롭지 않게 고음을 낮춘 스테레오 파일로 만듭니다(예전에는 폰에서 이퀄라이저를 걸었는데, 한쪽 채널 녹음에 걸면 왼쪽 스피커로만 나오는 차가 있었습니다).
웹 화면 위쪽의 날짜에서 지난 7일 기사 목록을 골라 볼 수 있습니다(서버가 `archive/<날짜>.json`으로 남김).
농업 신문과 비료 뉴스는 언론사마다 바이오플랜·비료·탄소중립·벼·과수 같은 말이 든 기사를 먼저 고릅니다(`feeds.json`의 `boost`, 앞 줄일수록 먼저).
서버 원고는 GitHub 예약 실행이 몇 시간씩 늦는 일이 있어, 'Morning alarm'이 전날 밤에 깨어나 기다렸다가 새벽 4시 40분과 5시 50분에 직접 만듭니다.

- 설치·기사 목록: https://kimyh1981.github.io/newsclipping/
- 갤럭시 앱(APK): https://github.com/kimyh1981/newsclipping/releases/latest/download/newsclipping.apk
- 언론사별 기사: https://kimyh1981.github.io/newsclipping/briefing.json (앱과 웹이 읽는다)
- 기본 언론사 원고: https://kimyh1981.github.io/newsclipping/briefing.txt (아이폰 단축어가 읽는다, 주말·공휴일에는 빈 파일)

## 구성

| 부분 | 하는 일 |
|---|---|
| `tools/collect.js`, `tools/naver.js`, `feeds.json` | 매일 새벽 5시(한국 시간) 헤드라인을 모아 `briefing.json`·`briefing.txt`를 만든다. 신문은 네이버 '신문보기'의 그날 1면 기사, 지면이 없는 통신사·방송은 언론사가 고른 '주요 뉴스'를 읽고(`naver`, `front`), 안 되면 언론사 RSS, RSS가 막히면 구글 뉴스로 대신하고, 같은 사건은 한 번만, 제목은 소리 내어 읽기 좋게 다듬는다. `lang`이 붙은 섹션(베트남)은 베트남판 구글 뉴스에서 찾아 제목을 구글 번역으로 옮긴다 |
| `tools/holidays.js` | 주말·공휴일이면 `briefing.txt`를 비운다. 공휴일은 공공데이터포털 특일 정보(`DATA_GO_KR_KEY`), 실패하면 내장 목록 |
| `js/brief.js` | 고른 언론사로 섹션과 원고를 만드는 규칙 (서버·웹 공용, 앱의 `Brief.java`가 같은 규칙. `tests/fixtures`로 둘을 맞춘다) |
| `index.html`, `js/app.js` | 기사 목록, 듣기 버튼, 언론사 체크 목록, 설치 안내 |
| `android/` | 갤럭시 앱. 차 블루투스 연결(ACL_CONNECTED)을 받아 평일 6~8시에 하루 한 번 원고를 받아 미디어 음량으로 읽고, 연결이 끊기면 멈춘다 |
| `.github/workflows/pages.yml` | 테스트 → 원고 수집 → Pages 배포 (push, 매일 05:00·05:40) |
| `.github/workflows/news-check.yml` | PR마다 실제 출처·번역을 불러 원고를 로그로 보여 준다 |
| `.github/workflows/android.yml` | 앱 단위 테스트·APK 빌드, main이면 릴리스로 올려 설치 링크를 갱신 |

## 처음 한 번 설정 (저장소 주인)

1. Settings → Pages → Build and deployment → Source를 **GitHub Actions**로.
2. Settings → Secrets and variables → Actions → `DATA_GO_KR_KEY` (공공데이터포털 인증키, 「한국천문연구원_특일 정보」 활용신청).

## 갤럭시 앱

설치 링크를 휴대폰에서 열어 APK를 받아 설치합니다. 플레이스토어 앱이 아니라서 '출처를 알 수 없는 앱 설치'를 한 번 허용해야 합니다.
앱에서 권한(블루투스·알림), 배터리 '제한 없음'(Android 12 이상에서 차 연결 순간 백그라운드로 시작하려면 필요), 차 블루투스를 고르면 끝입니다.
차를 고르지 않으면 오디오 블루투스 기기(차 오디오·헤드셋)가 연결될 때 모두 반응합니다. 시간대와 평일만 여부는 앱에서 바꿀 수 있습니다.

차에서 자동으로 읽기 시작하면 **자막 화면**이 뜹니다. 지금 읽는 헤드라인이 큰 글씨로 나오고, 화면을 누르면 그 기사 전체를 읽은 뒤 다음 헤드라인으로 넘어갑니다.
화면이 꺼져 있거나 다른 앱을 쓰는 중에도 뜨게 하려면 앱의 '다른 앱 위에 표시 (자막 화면용)'를 한 번 허용하세요. 읽는 중 알림을 눌러도 자막 화면이 열립니다.

APK는 `android/app/release.keystore`로 서명합니다. 같은 키로 서명해야 새 버전이 기존 앱 위에 업데이트로 설치됩니다.
저장소가 공개라 키도 공개되어 있으니, 가족·지인 밖으로 널리 배포하려면 키를 새로 만들어 저장소 비밀값으로 옮기고 `KEYSTORE_PASSWORD`를 바꾸세요.

## 신경망 음성으로 읽기

배포 작업이 매일 새벽 원고 줄(인사·연결 말·언론사 소개·헤드라인, 기본 언론사의 요약·본문)을 신경망 음성으로 녹음해 `audio/`에 올리고,
갤럭시 앱은 녹음된 줄을 그 파일로, 나머지는 폰 음성으로 읽습니다. 녹음이 안 되는 날에도 앱은 폰 음성으로 그대로 읽습니다.

- 기본: **MS 엣지 신경망 음성**(무료, 키·카드 없음, 선희 `ko-KR-SunHiNeural`). 엣지 브라우저 '소리 내어 읽기'를 공개 도구 [edge-tts](https://pypi.org/project/edge-tts/)로 쓰는 비공식 방식이라 언제든 막힐 수 있습니다. 막히면 수집 기록에 '음성 녹음 실패'가 남고 앱은 폰 음성으로 읽습니다.
- 목소리 바꾸기: 저장소 Settings → Variables의 `TTS_VOICE` (예: 남성 `ko-KR-InJoonNeural`, `ko-KR-HyunsuMultilingualNeural`)
- 녹음 끄기: Variables의 `TTS_ENGINE=off`
- 구글 클라우드 음성(Chirp 3 HD, 카드 등록 필요): 비밀값 `GOOGLE_TTS_KEY`에 Cloud Text-to-Speech API 키를 넣으면 그쪽으로 녹음합니다. 하루 25,000자로 막아 둡니다.

같은 날 다시 배포하면 이미 녹음한 줄은 다시 녹음하지 않습니다(작업 캐시). 녹음된 줄은 앱의 말 빠르기 설정을 따르지 않습니다.

## 아이폰 (차 화면)

아이폰 자동화(블루투스 → 차 → 연결될 때, 즉시 실행)의 동작을 **URL 열기** `https://kimyh1981.github.io/newsclipping/?car` 하나로 둡니다. 평일 아침 6~8시이고 쉬는 날이 아니면 화면 전체에 '누르면 읽어요' 화면이 뜨고, 한 번 누르면 서버에 녹음된 음성(없는 줄은 브라우저 음성)과 자막으로 끝까지 읽습니다. 사파리는 사람이 한 번 눌러야 소리를 낼 수 있어 첫 터치는 필요합니다.

## 아이폰 단축어 만들기 (누르지 않고 Siri 음성으로) (한 번만, 아이폰에서)

아이폰은 앱이 블루투스 연결을 알아차리는 것을 허용하지 않아 단축어로 합니다. 단축어 파일은 iCloud에 로그인한 기기에서만 서명할 수 있어(GitHub의 맥 환경에서 `shortcuts sign`은 'iCloud 로그인 필요'로 막힘), 아이폰에서 한 번 만들어 iCloud 링크로 공유합니다. 다른 사람은 링크로 추가만 하면 됩니다.

1. 단축어 앱 → **+** → 이름 '뉴스클리핑'
2. **URL**: `https://kimyh1981.github.io/newsclipping/ios/at/` 를 쓰고, 키보드 위 변수에서 **현재 날짜**를 넣은 뒤 그 변수를 눌러 날짜 형식 **사용자 지정** `H`로 바꾸고, 이어서 `.txt`
3. **URL의 콘텐츠 가져오기** → **텍스트 말하기** (언어 한국어, Siri 음성)
4. 단축어 공유 → **iCloud 링크 복사**, 그 링크를 `js/app.js`의 `SHORTCUT_URL`에 넣으면 웹 화면에 '단축어 추가' 버튼이 생깁니다.

`ios/at/<시>.txt`(0~23)는 수집기가 만듭니다. 6·7시 파일에만 기본 언론사 원고(표준 발음법·띄어 읽기 규칙 적용)가 들어 있고, 다른 시간과 쉬는 날에는 빈 파일이라 아무것도 읽지 않습니다.

언론사를 골라 듣고 싶으면 웹 화면의 '언론사 골라 듣기 (고급)'대로 만듭니다. `ios/<언론사 id>.txt`는 언론사마다 따로 만든 조각 원고이고, `open`·`close`는 인사와 맺음말입니다.

받는 사람은 링크로 단축어를 추가한 뒤 자동화 → 블루투스 → 차 → 연결될 때, 즉시 실행 → '뉴스클리핑'만 직접 연결합니다 (Apple이 자동화는 링크로 공유하지 못하게 합니다).

## 개발

```
npm test                       # 수집기·원고·공휴일·화면 테스트 (네트워크 없이)
npm run collect                # 실제 RSS를 모아 dist/에 원고 생성
cd android && gradle testReleaseUnitTest assembleRelease   # Android SDK 필요
```
